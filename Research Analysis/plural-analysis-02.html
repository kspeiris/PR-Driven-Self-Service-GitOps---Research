5. PR creation & conflict model


There are two different concepts that should not be mixed:






🟦 Existing PR / duplicate


Before creating another change, an implementation can look for an existing open PR/branch for the same logical change and reuse/update it where supported.






🟨 Mergeability


The Git provider is the authority for whether the PR can merge cleanly. A PR may become conflicting when its target branch changes after the PR was created.






🟥 Resolution


Detecting a conflict is not the same as automatically resolving it. The supplied material does not document automatic merge-conflict resolution as a native Plural feature.

The supplied research for Project 702 proposes using the Git provider API to inspect PR mergeability and explicitly treats automatic merge-conflict resolution as a non-goal. This is therefore shown here as the distinction between provider-reported state and platform handling.
